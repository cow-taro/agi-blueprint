# 編集計画 → 承認 → 実行

## トリガー

次のいずれかなら、**最初の Edit 前**に本スキルに従う:

- 実装・修正・リファクタ・ドキュメント更新・設定変更の依頼
- 調査の結果、ファイル変更が必要と判断したとき

## 依頼は承認ではない

依頼を受けたら:

1. 調査（read_file / search_files 等）で方針を固める
2. **編集計画**を書く
3. 提示前に本位チェック（下）を通す
4. 計画を提示する
5. ユーザーの **OK / 承認 / 実行して** を待つ
6. 承認後のみ、ファイル編集ツール（apply_diff / write_to_file / search_and_replace / insert_content 等の実際の編集系ツール）を使う

**1 ファイルずつ承認は不要。** 1 依頼 = 1 計画（複数ファイルをまとめてよい）。

## 計画提示前の自己チェック（必須）

計画をユーザーに出す直前に、**この計画の文面そのもの**に対して `rules/02-response-self-check.md` の自己チェックを回す。免除される項目はない。特に次を見る。

- 参照を 1 件ずつ実在確認したか（行番号・記号アンカー・番号だけ・未定義の短縮名を書いていないか）
- 一般名詞を固有名詞のように使っていないか（`rules/00-governance-core.md` の「2. 参照の許可形と禁止形」）
- 事実として書く文に、このターンで見た根拠があるか（見ていない断定・矛盾した断定を残していないか）
- 同じ内容を二度書いていないか
- 聞かれたことに答えているか
- 新しいファイル・名前・番号を作るなら、既存に入らないか・名前は中身と一致するか・番号は重要度で決めたか

引っかかったら直してから提示する。未確認のまま計画を出さない。

## 編集計画テンプレート

```markdown
## 編集計画（承認待ち）

### 依頼の理解
（ユーザーが求めていることを 1〜2 文）

### 変更ファイルと修正方針
| ファイル | 修正方針 |
|---|---|
| （docs/plans 配下の md） | （何をどう変えるか） |
| （ソースファイル） | （何をどう変えるか） |

### 変更しないもの
- （スコープ外・触らないファイルや挙動）

### 実装前グリーン（ソースを変える計画のとき必須）
- 影響範囲の既存テスト: （ファイル / マーカー / コマンド）
- 実行済みか: 未実行なら**ソース編集の前**に実行する。結果（件数・pass/fail・ベース SHA）を計画に書く
- 既に赤なら実装しない。コミット履歴で原因を特定してから報告する

### 実行順序
1. ...
2. ...

### 確認したい点
- （あれば。なければ「なし」）

### 本位チェック（取り違え不能か）
- この計画文面は推測なしで一意に辿れる。曖昧アンカー・すり抜けなし

---
承認いただければ、上記の範囲だけ実行します。
```

## 禁止

- 計画提示前のファイル編集
- 本位違反（曖昧アンカー・すり抜け・推測必須の略記）を含む計画の提示
- 依頼語（「進めて」「作成して」等）を承認とみなすこと
- 計画外ファイルの変更
- ユーザーの明示指示なしの `git commit` / `git push`

## 承認後

- 計画どおりに実行。完了報告は事実のみ（テスト未確認のまま「デグレなし」「完了」と断定しない）
- 途中で方針変更が必要 → 停止し、**新しい編集計画**を提示

# 初期設定ウィザード（setup-wizard）

## 目的

`SETUP-CHECKLIST.md` の棚卸し項目を、AI が対話的に質問して埋める。人間が checklist を手で編集しなくても、質問・サジェストに答えるだけで初期設定が完了する。

## モード判定（最初にやる）

- **既存プロジェクト適用モード**: すでにソースコード・ドキュメントが存在するプロジェクトへ、このテンプレートを後から適用する。→ 手順 1 の解析フェーズを行う
- **新規プロジェクトモード**: これから始めるプロジェクト。解析するものが無い。→ 手順 1 をスキップし、手順 2 で直接質問する

## 手順 1: 既存プロジェクトの解析（既存プロジェクト適用モードのみ）

既存のソースコードとドキュメントの解析で、SETUP-CHECKLIST の必要項目は高い確度で推定できる。推測で埋めず、**解析結果を証拠としてサジェストする**。

### 解析対象と、そこから分かること

| 解析対象 | 分かること | 対応する SETUP-CHECKLIST 項目 |
|---|---|---|
| ドキュメントディレクトリ（`docs/` 等の一覧）・README | ドキュメント正本の置き場所・プロジェクトの目的表現 | A1・A3 |
| CI 設定（`.github/workflows/*.yml` 等の `on.push.branches`・テストジョブ） | 保護ブランチ相当の実名・テスト実行コマンド | A6・A5 |
| テスト設定（`pytest.ini`・`package.json` 等）とテストディレクトリ | テストフレームワーク・マーカー・実行コマンド・golden の概念の有無 | A5・B3 |
| `git branch -r` とリモートの状態 | ブランチ実名（本番・検証・残置の区別。`origin/HEAD` が何を指していても workflows 設定を正とする） | A6 |
| DB 利用の有無（接続設定・マイグレーション・スキーマファイル） | MySQL 関連 skills の要否 | C1 |
| 既存の手順書・障害記録・設定差異 | プロジェクト固有前提の候補 | A7 |

### 解析結果の構造化

- 解析結果を `templates/adoption-analysis-template.md` に沿った構造化 md（解析日時・読んだファイルの実名・項目ごとの候補値と確度・根拠）として作成する。
- md の作成はファイル変更なので、`skills/edit-plan-approval/SKILL.md` に従い編集計画の承認を得てから作成する。
- 分からなかった項目は「不明」と明示し、手順 2 で質問する。推測を事実として書かない。

## 手順 2: A 章必須項目のサジェストと質問（未入力のまま運用開始禁止）

- A 章の項目を 2〜4 項目ずつのバッチで提示する。各項目には、解析結果からの候補値（確度つき）または選択肢をつける。
- 候補値は「サジェスト」であり確定ではない。ユーザーの確認を取ってから採用する。推測できない項目は素直に質問する。
- すべての A 章項目が確定するまで次の手順へ進まない。

## 手順 3: 書き込み（編集計画承認制）

- 収集した値を「どのファイルのどの節へ書くか」の一覧（編集計画）として提示し、明示承認を得てから書き込む。依頼・回答は承認にならない。
- 書き込み先の対応:
  - A1 → `rules/00-governance-core.md` の「0. 最上位目的（羅針盤）」
  - A3・A4 → `rules/01-workflow-gates.md` の「2. doc-first」と `skills/backend-test-first/SKILL.md` の「0. 作業計画」
  - A5 → `rules/03-test-before-implementation.md`、`skills/backend-test-first/SKILL.md`、`skills/snapshot-test-debugging/SKILL.md` への実名反映
  - A6 → `skills/git-repo-operations/SKILL.md` の「0. ブランチ対応表（サンプルを実名へ置き換える）」
  - A7 → `templates/project-premises-template.md` を複製した前提ファイルの作成
- 書き込み後、プレースホルダが残っていないかを置き換え漏れ確認として読み返す。
- ツリーを分割して配置した場合は、ファイル間の相互参照（`rules/`・`skills/`・`templates/` の相対パス）を採用後の実パスへ読み替える（関連 md の同期反映）。

## 手順 4: B 章の選択質問（カスタマイズ）

- B 章を 1 つのバッチで質問し、選択結果を該当ファイルへ反映する（同じく編集計画承認制）。

## 手順 5: C 章の削除提案

- C 章に当てはまるスキル・節を列挙し、削除提案を出す。削除も承認制。黙って削除しない。
- 削除するときは、残るファイルから削除対象への参照箇所もあわせて外す。

## 手順 6: 完了レポート

- 入力済み項目・未入力項目・反映したファイル・削除したスキル・次に読むべき md を一覧で出す。
- 未入力の A 章必須項目が残っている場合、運用開始前に完了を促す。

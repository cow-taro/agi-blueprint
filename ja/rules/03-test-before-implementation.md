# 実装前のテスト先行（要約）

既存の挙動を変える変更（バグ修正・セキュリティ対応・性能改善・リファクタ）は、下記の正本の手順でのみ着手する。

- 一気通貫手順の正本: `skills/backend-test-first/SKILL.md` の「固定手順（この順以外で実装禁止）」
- 記入用ひな形: `templates/desired-red-gate-checklist.md`
- テスト実行・失敗解析: `skills/snapshot-test-debugging/SKILL.md`

## 0. 適用対象と例外

- 対象: 既存挙動を変えるすべての変更
- 例外（理由を明示し、人間の承認がある場合のみ）: ドキュメントのみの変更／テストコードのみの追加／テスト基盤で覆えない対象（画面のないバッチ・外部連携・インフラ設定等。代替の証拠を提示して承認）

## 1. 実装前ゲート

- 影響範囲の**既存**テストを実際に実行し、全件緑を確認してからソースを変える。実行が確認である。「以前緑だったはず」は確認にならない
- 実行したコマンド・件数・pass/fail・ベース SHA を plan md に書く。1 件でも赤なら実装に進まず、コミット履歴から原因を特定して報告する
- テストの裏付けなしに「動作を保証」「デグレなし」「問題なし」と表現しない

# テスト実行手順書（test-runbook・生きた正本）

使い方: このファイルを複製して、開発環境ごとの確定コマンドと厳密な実行手順を記入し、**運用しながら追記編集し続ける**。テストは回数が多く、環境差や残留プロセス・実行中テストとのコンフリクトで結果が壊れやすい。だからこそ、ここに載せるコマンドは「**最終確認日の時点で、そのまま実行して成功したもの**」だけに限定する。壊れた・変わったら、先にこの手順書を直してから次へ進む。

## 2. 実行前の厳密手順（毎回・この順で）

1. **残留プロセスの確認と停止**
   ```bash
   ps aux | grep <server / pytest の実名> | grep -v grep
   ```
   - 見覚えのある自分の残留プロセスだけを、**内容を確認してから** kill する。無関係なプロセスを殺さない。
2. **実行中テストとのコンフリクト確認**
   - 同じ DB・同じポートを使う別の pytest / サーバー / 手動実行が動いていないかを確認する。動いていれば終了を待つか、自分のものだけ止めてから実行する。**並列実行はテスト結果と DB 状態を壊す。**
3. **DB 状態の判定**: seed / dump / スキーマを変えたなら、先にリセット（物理スナップ導入済みならスナップ取得）してから実行する。リセットで消える変更（インデックス等）を適用した状態で測るなら、リセットをスキップする方式で実行する。
4. **権限が必要なコマンドは、ツール呼び出しの引数に権限フィールドを実際に入れてから送る**（`skills/snapshot-test-debugging/SKILL.md` の「実行権限は引数に実際に入れる（送信前点検・絶対）」）。
5. **出力を握りつぶさない**（`2>/dev/null` / `| tail` / `| head` 等の禁止。`skills/snapshot-test-debugging/SKILL.md` の「0. コマンド出力を握りつぶさない（絶対）」）。

## 3. 実行中・実行後

- **テストは 1 度に 1 実行。** 複数スイートを並列に回さない。
- 想定外に失敗したら、省略フラグなしの完全リセットで再実行して、DB 状態が原因かを切り分ける。
- 実行結果（コマンド・件数・pass/fail・所要時間）を作業ログ（`templates/work-log-skeleton.md` 由来）へ記録する。
- コマンドを変えて実行したら、**この手順書の確定コマンド表を先に更新する。**

## 4. この手順書の保守ルール

- 本書は**生きた正本**である。環境が変わる・コマンドが変わる・失敗するたびに追記編集し、「確定コマンド表」を常に真に保つ。
- 本書が古いと、以後の全テスト実行が不正確になる。md の更新はコード更新とセット（`rules/01-workflow-gates.md` の「4. 検収後の md 反映（終点処理）」）。
